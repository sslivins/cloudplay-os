CLOUDPLAY OS IS AN UNSIGNED, HARDWARE-UNVALIDATED KIOSK PREVIEW.

The fixed cloudplay account (UID 1000) and root have locked passwords.
TEMPORARY DEVELOPMENT SSH IS ENABLED: user cloud, password cloud.
This is an explicitly PUBLIC default credential, not a production secret.
The separate cloud account has password-required sudo and can read/change the
whole system, including browser data. Use only on a trusted development network;
do not expose port 22 to the Internet. Root and cloudplay SSH login are denied.
Set CLOUDPLAY_DEVELOPMENT_SSH=0 in the build config to remove this preview access
from newly built images. This exception must be removed before production.
There is no OS owner wizard or desktop.
greetd opens a real PAM/logind session, then runs the minimal Wayland compositor
and Chromium as cloudplay. Never add --no-sandbox, root-browser execution or
remote-debugging switches. The normal Chromium sandbox remains enabled.

Anyone with physical access can use the persisted service/browser sessions.
Browser profiles are private to cloudplay (0700) but are NOT encrypted at rest.
The basic browser password store avoids a desktop keyring unlock dialog; do not
save unrelated passwords. Kiosk mode is an appliance UI, not an isolation or
browser navigation security boundary. Protect the device and removable media.

Home and leave confirmation are native, unprivileged Wayland windows.
The host shortcut uses an owner-only Unix socket, not a website-accessible HTTP
API. Only fixed GFN/Xbox launch actions exist; the root network helper gains no
process-control privileges. Returning Home stops the owned browser user cgroup
but does not erase sign-in. Same-user native processes remain trusted.
The input reader opens only classified non-keyboard gamepads; no broad input
group membership is granted. Xbox compatibility and gameplay are unvalidated.

All four custom Chromium packages are apt-held. Normal OS upgrades DO NOT
deliver browser security fixes. Maintainers must review Chromium advisories,
replace all four packages together, update the digest manifest, and retest.
The extension is root-owned/read-only to cloudplay and updated only by an
administrator with an independently reviewed commit and archive digest.
There is no automatic browser/extension updater, signed OTA or verified boot.

Network provisioning files on the boot partition are privileged configuration.
Ethernet DHCP, network-only onboarding and first-boot network-config are
supported by the source. The setup browser has its own ephemeral profile and
normal sandbox. The root network helper cannot read user homes and accepts
only narrow validated network operations; it never logs network passwords.
An optional phone hotspot uses fresh WPA credentials displayed locally; its
portal is AP-interface-only and closes before joining the home LAN.
There is no OS account wizard, terminal greeter or recovery partition.
Development recovery can use ssh cloud@DEVICE_IP and password-required sudo.
With development SSH disabled, recovery is offline editing or reflash;
never overwrite a running root filesystem. Profiles contain session credentials.

Checksums detect corruption, not publisher identity. A separately reviewed
signing/trust/revocation design is required before trusted public distribution.
Local HEVC fixtures are not proof of GFN gameplay, 4K decoding or HDR output.
